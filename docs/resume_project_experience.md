## 指标口径（面试必须如实说明）

- 5 项 100% 指标来自当前 3 条固定离线 Benchmark，适合作为回归测试基线，**不能**表述为生产准确率。
- P50/P95 来自规则解析、本地 Hash Embedding 和内存 Repository 的 100 次运行；接入 OpenAI、Milvus 或真实业务数据库后，端到端时延会显著增加，需要重新压测。
- 当前产品库只有 3 个演示 SKU；生产化应扩大 SKU、补充人工标注询盘集，并按国家、品类和询盘完整度分层评估。

## 面试口述版（约 60 秒）

我做的是一个外贸询盘处理 Agent。它解决的是销售收到英文 RFQ 后，需要在多个环节来回切换的问题。我把流程拆成 6 个节点：解析询盘、检查信息完整性、产品检索、产品匹配、调用价格库存交期规格工具，以及生成英文回复。缺产品、数量或目的国家时，系统不会贸然报价，而是自动生成澄清问题；信息完整时才进入检索和报价。

技术上，我让 LLM 或规则解析器只负责理解自然语言，价格和库存等事实必须由工具返回，避免模型编造。现在项目有 3 条固定 Benchmark，5 项离线指标都是 100%，但我会说明这只是小规模回归基线。前端把中间字段、候选产品、匹配理由和工具调用全部可视化，方便销售审核和面试演示。
